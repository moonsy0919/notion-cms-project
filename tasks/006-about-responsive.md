# Task 006: 소개(About) 페이지 완성 + 반응형 디자인 & UX 검증

## 개요

소개 페이지의 정적 자기소개 텍스트와 기술 스택 카드를 최종본으로 완성합니다.
이후 모든 페이지를 대상으로 반응형 레이아웃과 사용자 경험을 검증합니다.
모바일(375px), 태블릿(768px), 데스크톱(1280px) 세 가지 뷰포트에서 레이아웃 깨짐 여부를 점검하고,
다크 모드 색상 대비를 전체 페이지에 걸쳐 확인합니다.
발견된 문제는 이 Task 내에서 수정 완료합니다.

## 관련 파일

- `app/about/page.tsx` — 소개 페이지 (자기소개 + 기술 스택 카드 최종본)
- `app/page.tsx` — 홈 페이지 반응형 점검
- `app/projects/page.tsx` — 프로젝트 목록 페이지 반응형 점검
- `app/projects/[id]/page.tsx` — 프로젝트 상세 페이지 반응형 점검
- `components/layout/Header.tsx` — 모바일 헤더/네비게이션 점검
- `components/projects/ProjectCard.tsx` — 카드 레이아웃 반응형 점검
- `components/projects/ProjectFilters.tsx` — 필터 버튼 반응형 점검

## 수락 기준 (Acceptance Criteria)

- [ ] `/about` 페이지에 정적 자기소개 텍스트와 기술 스택 카드가 최종본 형태로 표시된다
- [ ] 모바일(375px)에서 모든 페이지의 레이아웃이 깨지지 않는다
- [ ] 태블릿(768px)에서 모든 페이지의 레이아웃이 깨지지 않는다
- [ ] 데스크톱(1280px)에서 모든 페이지의 레이아웃이 깨지지 않는다
- [ ] 다크 모드에서 전체 페이지 컴포넌트의 색상 대비가 가독성 기준을 충족한다
- [ ] 네비게이션 → 프로젝트 목록 → 상세 → 뒤로가기 사용자 플로우가 모든 뷰포트에서 정상 동작한다
- [ ] 모바일 뷰포트에서 `ProjectFilters` 버튼이 가로 스크롤 또는 줄바꿈으로 올바르게 표시된다

## 구현 단계

1. `app/about/page.tsx` — 자기소개 텍스트 및 기술 스택 카드 최종본으로 완성
2. 브라우저 DevTools Device Toolbar를 활용하여 각 뷰포트(375px / 768px / 1280px)에서 전체 페이지 순회 점검
3. 발견된 반응형 레이아웃 문제(넘침, 겹침, 여백 등) 수정 — Tailwind 반응형 클래스(`sm:`, `md:`, `lg:`) 보완
4. 라이트 모드와 다크 모드를 전환하며 모든 페이지의 텍스트/배경/배지 색상 대비 확인
5. 색상 대비가 부족한 요소를 CSS 변수 또는 Tailwind 다크 모드 클래스로 수정
6. 네비게이션 → 프로젝트 목록 → 상세 → 브라우저 뒤로가기 플로우를 모바일·데스크톱 각각 확인

- [ ] 모바일(375px): 홈, 프로젝트 목록, 프로젝트 상세, 소개 페이지 레이아웃 확인
- [ ] 태블릿(768px): 홈, 프로젝트 목록, 프로젝트 상세, 소개 페이지 레이아웃 확인
- [ ] 데스크톱(1280px): 홈, 프로젝트 목록, 프로젝트 상세, 소개 페이지 레이아웃 확인
- [ ] 라이트 모드에서 전체 페이지 색상 대비 확인
- [ ] 다크 모드에서 전체 페이지 색상 대비 확인
- [ ] 모바일 뷰포트에서 헤더 네비게이션이 올바르게 표시되는지 확인
